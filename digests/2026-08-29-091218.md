**Anthropic Engineering: An update on recent Claude Code quality reports**
https://www.anthropic.com/engineering/april-23-postmortem

Anthropic published a transparent postmortem on why Claude Code felt degraded for some users over the past month — tracing it to three separate, overlapping issues. First, in March, Claude Code's default reasoning effort was quietly lowered from high to medium to reduce latency, but users noticed and reported reduced intelligence; it was reverted in April, and all models now default to high or xhigh effort. Second, a caching optimization shipped in late March had a bug: instead of clearing stale reasoning once after a long idle session, it wiped prior reasoning on every subsequent turn, making Claude seem forgetful and repetitive. This was fixed April 10. Third, a system prompt change to reduce verbosity — "keep text between tool calls to ≤25 words" — turned out to hurt coding quality and was reverted April 20. Anthropic reset usage limits for all subscribers and outlined several process improvements: broader internal use of the public build, a wider eval suite for system prompt changes, and tighter controls before any change trading intelligence for another property.

**Anthropic Engineering** 发布了一篇透明的事后复盘，解释了过去一个月部分用户反映 Claude Code 质量下降的原因——根源是三个独立但相互叠加的变更。第一，3 月份 Claude Code 的默认推理强度从 high 悄悄调低至 medium 以减少延迟，但用户明显感知到智能下降，已于 4 月恢复，现在所有模型默认使用 high 或 xhigh 推理强度。第二，3 月底上线的一个缓存优化存在 bug：本应在会话空闲超过一小时后清一次旧的推理记录，结果变成了每次对话都清除，导致 Claude 表现得健忘且重复，已于 4 月 10 日修复。第三，一条旨在减少冗长输出的 system prompt 变更——"工具调用之间的文字不超过 25 个词"——事后发现严重影响了代码质量，已于 4 月 20 日撤回。Anthropic 向所有订阅用户重置了使用配额，并宣布了多项流程改进措施。

**Anthropic Engineering: Scaling Managed Agents — Decoupling the brain from the hands**
https://www.anthropic.com/engineering/managed-agents

Anthropic's engineering team published a deep technical post on how they redesigned Managed Agents — their hosted long-horizon agent service — around a key architectural insight: decouple the "brain" (Claude and its harness) from the "hands" (sandboxes and tools) and the "session" (the durable event log). The old design put everything in one container, creating fragile "pets" — if a container failed, the session was lost. The new design treats containers as cattle: the harness calls the sandbox via `execute(name, input) → string`, exactly like any other tool. If the container dies, Claude catches the failure as a tool-call error. If the harness crashes, a new one can resume from the session log with `wake(sessionId)`. Security improved too: credentials never live in the same environment as Claude's generated code — OAuth tokens go into a vault, and a proxy handles external calls. The architectural payoff: p50 time-to-first-token dropped ~60% and p95 dropped over 90%. The post frames Managed Agents as a "meta-harness" — opinionated about the interfaces (session, harness, sandbox) but unopinionated about the implementations, so it can accommodate models and harnesses that don't yet exist.

**Anthropic Engineering** 发布了一篇深度技术文章，介绍了 Managed Agents（其托管式长时 agent 服务）的架构重设计，核心洞见是：将"大脑"（Claude 及其 harness）与"双手"（沙盒和工具）以及"会话"（持久化事件日志）彻底解耦。旧设计将所有组件放在同一个容器中，形成脆弱的"宠物式"服务——容器崩溃则会话丢失。新设计让容器成为"牲口"：harness 通过 `execute(name, input) → string` 调用沙盒，就像调用任何其他工具一样。沙盒挂掉，Claude 将其视为工具调用错误；harness 崩溃，新的 harness 可通过 `wake(sessionId)` 从会话日志中恢复。安全性也得到提升：OAuth token 存入保险库，credentials 永远不出现在 Claude 生成代码所在的沙盒环境中。架构成效显著：首 token 到达时间（TTFT）p50 下降约 60%，p95 下降超过 90%。这篇文章将 Managed Agents 定义为一种"元 harness"——对接口有主见，但对实现保持开放，以便适应未来尚未出现的模型和 harness。
https://www.anthropic.com/engineering/managed-agents

**No Priors: Rethinking Legacy Data Infrastructure with Eon Co-Founders Ofir Ehrlich and Gonen Stein**
https://www.youtube.com/@NoPriorsPodcast

**The Takeaway:** In the AI era, enterprise data is the only true moat — but most of it is locked, unclassified, and invisible. The new threat isn't ransomware from hackers; it's agents inside your own organization with legitimate credentials doing damage at machine speed.

Ofir Ehrlich and Gonen Stein, co-founders of EON, a cloud backup and data-recovery platform built for the AI era, joined No Priors to discuss the seismic shift in how enterprises should think about their data. EON started as a disaster recovery company, but pivoted hard when it became clear that enterprise data had become the primary moat in an AI world where models, compute, and tools are rapidly commoditizing.

The episode opens with a striking data point: Google recently acquired Spirit Airlines' enterprise dataset out of bankruptcy for $10M — not the planes, not the routes, the data. Mercor was reportedly the competing bidder. This signals a new category: out-of-bankruptcy data acquisitions by AI companies hunting for high-quality, real-world datasets that synthetic data can't replicate.

Ehrlich and Stein argue that most enterprise data sits locked in forgotten servers and siloed business units, inaccessible not because it isn't there but because the organizational incentives are misaligned — business unit leaders protect their turf, data teams can't get access, and extracting the data safely without compromising production or compliance requires engineering resources no one wants to dedicate. EON addresses this by building a unified data foundation that maps, classifies, and continuously ingests data from across an organization — without touching production — applying semantic context layers and access controls so only the right data reaches AI workflows.

The security angle was the most urgent: where threats once came exclusively from human attackers like ransomware, EON is now seeing AI agents with legitimate permissions cause catastrophic data damage at machine speed — a table dropped, a dataset corrupted — and enterprises are only beginning to grapple with the scale. Six months ago, nobody wanted to discuss it; today, every leader Stein meets has either experienced it personally or fears it deeply. The prescription: assume breach, whether malicious or not, and build for rapid, granular recovery.

On the future of data infrastructure, Stein is clear: dashboards will proliferate, not disappear, because they're the only way to track what a swarm of interconnected agents is actually doing. Legacy ETL pipelines and BI tools were built for humans asking intentional questions; the agentic world demands infrastructure that can handle the full context of an organization's data, continuously, at scale — and existing tools like Fivetran and dbt, however excellent for their era, were never designed for it.

**No Priors：重新思考企业数据基础设施 — EON 联合创始人 Ofir Ehrlich 与 Gonen Stein**
https://www.youtube.com/@NoPriorsPodcast

**核心洞见：** 在 AI 时代，企业数据是唯一真正的护城河——但大多数数据被锁死、未分类、不可见。新的威胁不再是黑客发动的勒索软件攻击，而是你自己组织内部、持有合法权限的 agent 以机器速度造成的破坏。

EON 联合创始人 Ofir Ehrlich 和 Gonen Stein 走进 No Priors 播客，深入探讨企业在 AI 时代应如何重新认识自己的数据。EON 起初是一家灾难恢复公司，随后发现在模型、算力、工具都快速商品化的 AI 世界里，企业数据才是真正的核心壁垒，于是果断转型。

对话以一个引人注目的事实开场：谷歌近期以 1000 万美元从破产的 Spirit Airlines 手中购入了其企业数据集——买的不是飞机，不是航线，是数据。据报道竞标方还有 Mercor。这标志着一个新类别的出现：AI 公司通过破产程序收购高质量真实世界数据集，这是合成数据无法替代的。

Ehrlich 和 Stein 指出，大多数企业数据被封存在被遗忘的服务器和割裂的业务部门中，不是因为不存在，而是因为组织激励错位——业务负责人各守一亩三分地，数据团队拿不到访问权限，安全合规地提取数据又需要没人愿意投入的工程资源。EON 的解法是构建一个统一的数据基础层，在不影响生产环境的前提下，对全组织数据进行映射、分类和持续接入，并叠加语义上下文层与访问控制，确保只有合适的数据流入 AI 工作流。

安全议题是最紧迫的：此前的威胁主要来自勒索软件等外部人为攻击，而现在 EON 看到的是：持有合法权限的 AI agent 在机器速度下造成灾难性数据破坏——一张数据表被意外删除、一个数据集遭到污染——企业才刚刚开始意识到这种威胁的规模。六个月前没人愿意讨论这个话题；如今 Stein 遇到的每位企业领导人，要么亲身经历过，要么深感忧虑。处方是：无论恶意与否，都要假设系统已被攻破，并为快速、精细的数据恢复做好准备。

对于数据基础设施的未来，Stein 判断清晰：仪表盘不会消失，反而会激增——因为那是追踪相互协作的 agent 群体究竟在做什么的唯一方式。旧有的 ETL 流水线和 BI 工具是为"人类带着明确目的提问"这一场景设计的；agentic 世界需要能够以全组织视角、持续、大规模处理数据上下文的基础设施——而 Fivetran、dbt 这些工具，无论在各自时代多么出色，都不是为此而生的。
https://www.youtube.com/@NoPriorsPodcast
