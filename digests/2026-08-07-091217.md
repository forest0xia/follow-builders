**Claude Blog: "Building intelligent apps for Apple platforms with Claude in the Foundation Models framework"**

Anthropic is releasing Foundation Models framework support for Claude via a new Swift package, letting Apple developers call Claude directly through Apple's Foundation Models API. The on-device model handles fast, local tasks (summarization, extraction); Claude picks up the heavy lifting — multi-step reasoning, code generation, web search, data analysis — all within the same Swift view.

The key architectural insight: because Apple's framework returns typed Swift values through `@Generable` annotations, developers arrive at the Claude API call with clean, structured inputs rather than raw user text. This dramatically reduces prompt engineering overhead and makes the hand-off from on-device to cloud-hosted AI feel seamless. A journaling app can prompt locally, then ask Claude to find themes across months of entries. A study app can define a term on-device, then hand off to Claude for deeper reasoning. One experience, right model for each step.

The package is available on iOS 27, iPadOS 27, macOS 27, visionOS 27, and watchOS 27. Setup: add the package, sign in with your Anthropic API key, pass typed outputs from Apple's on-device model into a Claude request. The package handles streaming, tool calls, and structured responses back into SwiftUI.
https://claude.com/blog/claude-for-foundation-models

**The MAD Podcast with Matt Turck: "How to Build Long-Horizon AI Agents — Mitch Troyanovsky, Basis"**
https://www.youtube.com/@DataDrivenNYC/videos

**The Takeaway:** Getting AI agents to operate reliably for hours (not just minutes) is an architectural and behavioral problem, not a capability problem — and the key is treating context like your most precious resource, not an afterthought.

Mitch Troyanovsky is co-founder of Basis, a unicorn AI company building agents that do accounting work end-to-end — including complete tax return preparation. The episode is a genuine reference conversation for anyone building production AI systems.

**On what long-horizon really means:** LLMs have very large working memories but no short- or long-term memory by default. Once a task pushes past that working memory — ten minutes, twenty minutes, hours of autonomous operation — you hit fundamental limits. The art is in building harnesses that let LLMs be coherent over time despite this constraint.

**On context as the most precious resource:** Basis employees whisper into high-fidelity microphones throughout the day rather than typing. The reason: speech is far richer than text, and to an agent, more context is always better. "The English is more precious because the English affects the performance. The code does not affect the performance." Most engineers obsess over code abstraction and neglect the quality of their context — Mitch argues this is exactly backwards.

**On what "autonomous" actually means:** Autonomous doesn't mean unsupervised. It means "start to done" — but done means handing off with a clear record of decisions made, assumptions taken, and things to review. The analogy: a well-stacked PR where the engineer explains their big architectural choices, versus a 1,000-line PR that says "it's done, trust me." Accounting is no different. The goal is making it easy for the human reviewer to understand what the agent decided and why.

**On evals vs. real-world performance:** 100 evals passing is a start, but it doesn't prove generalization to production. If the agent is getting it right by going to Wikipedia, an accounting firm wouldn't hire it — and neither should you. True robustness comes from building agents that reason correctly, not ones that happen to score well on narrow benchmarks.

**On behavior specs and process design:** Building long-horizon agents is really like designing organizational processes — how do you get non-deterministic entities (people, AI) to coordinate reliably to solve a problem? The discipline Basis has developed is encoding best practices, professional standards, and explicit decision trees into behavior specifications — the thing the agent actually follows. This turns out to be more important than the code surrounding the agent.

**On accounting as the ideal proving ground:** Accounting is "an intelligence over the economy" — it compresses vast, unstructured real-world activity into structured insight that enables decisions by CEOs, the IRS, banks, and investors. That complexity, combined with the requirement for correctness, makes it an ideal domain for proving out long-horizon agent capabilities.

**MAD播客 Matt Turck：《如何构建长周期AI Agent——Mitch Troyanovsky，Basis》**
https://www.youtube.com/@DataDrivenNYC/videos

**核心洞察：** 让AI agent可靠地运行数小时（而非数分钟）是一个架构与行为问题，而非能力问题——关键在于将context视为最宝贵的资源，而不是事后才想到的东西。

Mitch Troyanovsky是Basis的联合创始人，Basis是一家估值独角兽级别的AI公司，其agent能端到端完成会计工作——包括完整的报税流程。这期节目是任何构建生产级AI系统的人都值得认真收听的参考对话。

**关于"长周期"的真正含义：** LLM拥有非常大的工作记忆，但默认没有短期或长期记忆。一旦任务超出这个工作记忆的范围——十分钟、二十分钟、数小时的自主运行——就会触及根本性的限制。这门艺术在于构建能让LLM在这一约束下保持连贯性的harness框架。

**关于context是最宝贵的资源：** Basis员工整天都对着高保真麦克风轻声说话，而不是打字。原因是：语音比文字承载的信息量大得多，而对agent来说，context越多越好。"英文（自然语言）才是最珍贵的，因为它影响性能。代码不影响性能。"大多数工程师痴迷于代码抽象，却忽视了context的质量——Mitch认为这恰恰搞反了。

**关于"自主"的真正含义：** 自主不等于无人监督。它的意思是"从开始到完成"——但"完成"意味着交付时附带清晰的决策记录、假设说明和待复核事项。类比是：一个工程师提交一个层次清晰、清楚解释了重要架构选择的PR，与提交一个1000行代码的PR并说"信我就好"——天壤之别。会计工作没什么不同。目标是让人类审核者能轻松理解agent做了哪些决策，以及为什么这么做。

**关于评测与真实世界性能：** 100个eval全部通过是个好的开始，但不能证明能泛化到生产环境。如果agent只是靠查维基百科得到了正确答案，会计事务所不会雇用它——你也不应该。真正的鲁棒性来自构建能够正确推理的agent，而不是恰好在狭窄benchmark上得高分的agent。

**关于行为规范和流程设计：** 构建长周期agent本质上就像设计组织流程——如何让非确定性的实体（人、AI）可靠地协调配合来解决问题？Basis形成的方法论是：将最佳实践、职业标准和明确的决策树编码成行为规范——agent实际遵循的东西。这比agent周围的代码更重要。

**关于会计是理想的试验场：** 会计是"经济的智能层"——它将巨大的、非结构化的现实世界活动压缩成结构化的洞察，为CEO、税务机关、银行和投资者的决策提供依据。这种复杂性，加上对正确性的严格要求，使其成为验证长周期agent能力的理想领域。
