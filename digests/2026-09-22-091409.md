## OFFICIAL BLOGS

**Claude Blog: Claude in Chrome is generally available**

Claude in Chrome is now generally available on all paid Claude plans, bringing autonomous browser-based actions to everyday users. Claude can now act in Chrome without requiring approval for every step — a safety classifier validates each action before it runs. The feature enables Claude to work in tools that don't natively connect to Claude, including internal dashboards, legacy systems, and vendor portals, using the user's existing logins.

On prompt injection defenses: Anthropic reports that with the full safeguard stack (probes + safety classifier), no attacks succeeded against Claude Sonnet 5 or Claude Opus 5, and only 0.3% succeeded against Fable 5. The attack surface against Opus 5 dropped from 3.8% (no safeguards) to 0% (full stack). Anthropic notes that "Prompt injection remains a moving target" and continues to invest in automated attack discovery and stronger classifiers.

Enterprise admins can limit Claude in Chrome to approved domains via Organization Settings. Claude in Chrome does not yet run on other Chromium browsers or mobile.
https://claude.com/blog/claude-in-chrome-generally-available

**Claude Blog：Claude in Chrome 正式全面开放**

Claude in Chrome 现已在所有付费 Claude 计划中正式上线，将自主浏览器操作带给普通用户。Claude 现在无需每一步都获得用户批准即可在 Chrome 中执行操作——每个动作在执行前都会经过安全分类器的验证。该功能使 Claude 能够在未原生连接 Claude 的工具中工作，包括内部仪表盘、遗留系统和供应商门户，并使用用户现有的登录凭证。

在 prompt 注入防御方面：Anthropic 报告称，在完整防护栈（probes + 安全分类器）下，Claude Sonnet 5 和 Claude Opus 5 的攻击成功率为 0%，Fable 5 仅为 0.3%。Opus 5 的攻击成功率从无防护状态下的 3.8% 降至完整防护下的 0%。Anthropic 指出"prompt 注入仍是一个移动靶标"，并持续投资于自动化攻击发现和更强的分类器。

企业管理员可通过组织设置将 Claude in Chrome 限制在已批准的域名范围内。Claude in Chrome 目前尚不支持其他基于 Chromium 的浏览器或移动端。
https://claude.com/blog/claude-in-chrome-generally-available
