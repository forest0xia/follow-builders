**Peter Yang** (AI educator and product strategist)

Peter Yang dug into X's open-source algorithm for fighting AI slop and found significant gaps. The platform uses a behavioral model called TweetSpamBot that analyzes up to 512 recent account actions — flagging patterns like TWEET_CREATE_BURST, QUOTE_TWEET_SPAMMER, and CONTENT_AMPLIFIER. The critical flaw: the model doesn't actually read post content, making it trivially easy for a coordinated AI content mill to keep posting template quote-tweet slop at high volume without triggering enforcement. His recommendation is for X to target accounts that repeatedly repurpose the same template across unrelated viral posts.

**Claude Blog — Building intelligent apps for Apple platforms with Claude in the Foundation Models framework**

Anthropic just made Claude available as a first-class citizen inside Apple's Foundation Models framework. Through a new Swift package, developers can now use Apple's on-device models for lightweight tasks (summarization, extraction) and hand off seamlessly to Claude when the job requires multi-step reasoning, code generation, web search, or data analysis — all within the same SwiftUI view.

The key technical unlock is that Apple's framework returns typed Swift values via @Generable annotations, which means developers arrive at the Claude API call with clean, structured inputs rather than raw user text. The integration streams Claude's response back into the same view, making it a single, coherent experience for the end user.

The practical implications are significant: a journaling app can surface personalized prompts on-device, then ask Claude to find patterns across months of entries. A study app can define a term locally and escalate to Claude when the student asks a complex follow-up. Available on iOS 27, iPadOS 27, macOS 27, visionOS 27, and watchOS 27 — developers can add the Swift package, sign in with an Anthropic API key, and start building.
https://claude.com/blog/claude-for-foundation-models

**Claude 博客——使用 Foundation Models 框架在 Apple 平台构建智能应用**

Anthropic 正式让 Claude 成为 Apple Foundation Models 框架中的一等公民。通过一个新的 Swift 包，开发者可以在轻量任务（摘要、信息提取）上使用 Apple 本地模型，而当任务需要多步推理、代码生成、网页搜索或数据分析时，无缝交接给 Claude——整个过程共享同一个 SwiftUI 视图。

核心技术突破在于：Apple 框架通过 @Generable 注解返回类型化的 Swift 值，开发者到达 Claude API 调用时已有干净的结构化输入，而非原始用户文本。集成方案将 Claude 的响应以流式方式回传到同一视图，为用户呈现一体化的连贯体验。

实际影响不可小觑：一个日记 App 可以在本地生成个性化提示词，再请 Claude 梳理数月记录中的规律；一个学习 App 可以在本地解释术语定义，当学生提出复杂追问时升级交给 Claude 处理。支持 iOS 27、iPadOS 27、macOS 27、visionOS 27 和 watchOS 27——开发者添加 Swift 包、登录 Anthropic API key，即可开始构建。

**The MAD Podcast with Matt Turck — How to Build Long-Horizon AI Agents**
*Guest: Mitch Troyanovsky, Co-founder of Basis*

**The Takeaway:** Passing 100 evals is not the same as being ready for production — and the English context you give an AI agent matters far more than whether your code is cleanly abstracted.

Mitch Troyanovsky co-founded Basis, a unicorn AI company whose agents run autonomously for hours or even days completing accounting work end to end — including entire tax returns. Accounting was the deliberate choice: it's one of the largest knowledge-work professions in the US (over 3 million practitioners), and it's fundamentally an intelligence layer over the economy, compressing a messy, unstructured real world into structured information that lets banks, investors, regulators, and executives make decisions. Getting agents to be coherent over that kind of work is the hard problem.

On what long-horizon actually means: Troyanovsky frames it as a spectrum of agency. Short-horizon agents (fetching weather, running a quick lookup) don't need to be coherent over time. Long-horizon agents — implementing a feature, building an entire Excel workbook, completing a tax return — might run for 10, 20, 30 minutes or more, and start hitting the fundamental limits of how LLMs work. His diagnosis: "LLMs have very large working memories and by default no short-term or long-term memory." The engineering job is to build harnesses that compensate for this.

On evals and production readiness: "Let's say you have 100 evals. Great. They all pass. That looks good. Are you confident that now generalizes to the real world? Our answer has been no. Even if you got it right 100 out of 100 times, if a person is just getting it right because they're going to Wikipedia, the accounting firm wouldn't hire them — and so they shouldn't hire us either." Evals measure pattern, not judgment.

On the Basis office's whispering culture: the entire team speaks into microphones rather than typing to their agents, because speaking is faster and AI agents actually prefer the extra unstructured context. "It's rude if somebody just blabbered and sent that to you as a Slack DM. But to an agent, they don't care. They would actually prefer it." And on context quality: "You'll see people freaking out over a code file that isn't abstracted properly, and yet their context is total shit. The English is more precious because the English affects the performance. The code does not affect the performance."
https://www.youtube.com/@DataDrivenNYC/videos

**MAD Podcast（Matt Turck 主持）——如何构建长时程 AI Agent**
*嘉宾：Basis 联合创始人 Mitch Troyanovsky*

**核心要点：**通过 100 个 eval 并不等于生产就绪——你给 AI agent 的英文上下文质量，远比你的代码是否抽象整洁更重要。

Mitch Troyanovsky 联合创始了 Basis，一家独角兽 AI 公司，其 agent 能自主运行数小时甚至数天，端到端完成会计工作，包括整份税务申报。选择会计是深思熟虑的：这是美国最大的知识工作职业之一（从业者超 300 万），本质上是经济体上方的一层智能，将杂乱无结构的真实世界压缩为结构化信息，帮助银行、投资者、监管机构和高管做出决策。让 agent 在这类工作中保持长时程连贯性，才是真正的难题。

关于"长时程"的定义：Troyanovsky 将其理解为一个 agency 的程度谱系。短时程 agent（查天气、快速检索）不需要随时间保持连贯。长时程 agent——实现一个功能、制作一份完整 Excel 报告、完成一份税务申报——可能运行 10、20、30 分钟甚至更长，开始触碰 LLM 的根本性局限。他的诊断是："LLM 的工作记忆很大，但默认没有短期或长期记忆。"工程工作就是构建 harness 来弥补这一缺陷。

关于 eval 与生产就绪："假设你有 100 个 eval，很好，全部通过，看起来不错。但你有把握这能推广到真实世界吗？我们的答案是否定的。哪怕 100 次中你答对了 100 次，如果一个人是靠查维基百科答对的，会计事务所不会雇他——我们也不应该被雇。"Eval 衡量的是模式，而非判断力。

关于 Basis 办公室的低声文化：整个团队对着麦克风说话而不是打字，因为语音更快，而 AI agent 其实更偏好那些非结构化的额外上下文。"把絮叨的语音直接作为 Slack DM 发给人类是很没礼貌的事，但对 agent 来说，它们不在乎，它们实际上更偏好这样。"关于上下文质量，他的判断是："你会看到有人对一个没有好好抽象的代码文件抓狂，但他们的上下文写得一塌糊涂。英文上下文更珍贵，因为英文影响性能，代码不影响性能。"
