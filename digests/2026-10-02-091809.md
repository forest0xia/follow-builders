### Anthropic Engineering

**How we contain Claude across products**

Anthropic's engineering team published a detailed breakdown of how they've architected containment for three Claude products — claude.ai, Claude Code, and Claude Cowork — each using a different isolation strategy matched to its user base and threat model.

The post identifies three layers of defense: the environment (sandboxes, VMs, egress controls), the model itself (probes, classifiers, system prompts), and the external content the agent can reach (MCP servers, plugins, web search). The key lesson: "the weakest layer is the one you built yourself" — their gVisor containers and hypervisors held up, while their custom-built proxies were the source of the biggest failures.

Two notable incidents are disclosed: a phishing attack in which a researcher got Claude to exfiltrate AWS credentials 24 out of 25 attempts by embedding instructions in a routine-looking "run this for me" prompt; and a third-party disclosure revealing that Cowork's egress allowlist correctly passed traffic to api.anthropic.com — which an attacker exploited to upload workspace files to their own Anthropic account using an embedded API key.

The guiding principle: "match isolation strength to the user's capacity for oversight. A developer who can read bash and a knowledge worker who can't are not running the same threat model."

https://www.anthropic.com/engineering/how-we-contain-claude

Anthropic 工程团队发布了一篇详细文章，介绍了他们为三款 Claude 产品——claude.ai、Claude Code 和 Claude Cowork——设计的遏制架构，每种产品都采用了与其用户群和威胁模型相匹配的不同隔离策略。

文章指出了三层防御：运行环境（沙箱、虚拟机、出口控制）、模型本身（probe 探针、分类器、系统提示词），以及 agent 可访问的外部内容（MCP 服务器、插件、网络搜索）。核心教训："自己构建的组件往往是最薄弱的"——他们的 gVisor 容器和虚拟机管理程序表现稳健，而自行构建的代理才是最大失败的来源。

文章披露了两起值得关注的安全事件：一是研究员通过将指令嵌入看似普通的"帮我运行这个"提示词，成功让 Claude 在 25 次尝试中的 24 次泄露了 AWS 凭证；二是第三方披露的漏洞，Cowork 的出口白名单正确放行了发往 api.anthropic.com 的流量，但攻击者利用嵌入的 API 密钥将工作区文件上传至其自己的 Anthropic 账户。

核心原则："将隔离强度与用户的监督能力相匹配。能读懂 bash 的开发者和不懂命令行的知识工作者，面临的威胁模型并不相同。"

https://www.anthropic.com/engineering/how-we-contain-claude

**An update on recent Claude Code quality reports**

Anthropic published a transparent postmortem on three separate changes that degraded Claude Code quality for some users between March and April, all now resolved as of April 20 (v2.1.116).

The three issues: (1) default reasoning effort was quietly changed from "high" to "medium" to reduce latency — users noticed the intelligence drop and it was reverted on April 7; (2) a caching optimization bug caused Claude to drop its entire reasoning history on every turn after a session went idle for over an hour, making it "forgetful and repetitive" — fixed April 10; and (3) a system prompt addition meant to reduce verbosity ("≤25 words between tool calls, ≤100 words in final responses") caused a measurable 3% drop in coding quality and was reverted April 20.

Because each change affected different traffic on a different schedule, the aggregate looked like broad, inconsistent degradation that was hard to reproduce internally. Anthropic is resetting usage limits for all subscribers and committing to bigger eval suites, ablation testing for every prompt change, and longer soak periods before shipping.

https://www.anthropic.com/engineering/april-23-postmortem

Anthropic 发布了一份透明的事后复盘，涉及三个分别导致 Claude Code 对部分用户质量下降的独立改动，均已于 4 月 20 日（v2.1.116）修复。

三个问题分别是：(1) 为降低延迟，默认推理力度从"高"悄悄调整为"中"，用户察觉到智能下降后已于 4 月 7 日回滚；(2) 一个缓存优化 bug 导致 Claude 在会话闲置超过一小时后，每轮都清空完整的推理历史，表现出"健忘和重复"——已于 4 月 10 日修复；(3) 一个旨在减少冗长的系统提示词添加（"工具调用之间不超过 25 字，最终回复不超过 100 字"）导致编程质量下降了可测量的 3%，已于 4 月 20 日回滚。

**Scaling Managed Agents: Decoupling the brain from the hands**

Anthropic Engineering describes the architecture behind Managed Agents, a hosted service in the Claude Platform for running long-horizon agent tasks. The core insight: they decoupled the "brain" (Claude and its harness) from the "hands" (sandboxes and tools) and the "session" (event log), treating each as an independent interface that can fail or be swapped without disrupting the others.

The previous coupled design meant a single container failure lost everything. The new architecture lets each component fail independently: if a sandbox crashes, it returns a tool error; if the harness fails, a new one resumes from the session log with `wake(sessionId)`. This dropped median time-to-first-token by 60% and p95 latency by over 90%.

The session log also solves context window limits for long tasks: rather than irreversibly compacting messages, the brain can interrogate context by fetching positional slices of the event stream — rewinding or skipping ahead as needed. "We can't predict what specific context engineering will be required in future models."

https://www.anthropic.com/engineering/managed-agents

Anthropic 工程团队介绍了 Managed Agents 的架构——这是 Claude 平台中用于运行长时程 agent 任务的托管服务。核心思路：将"大脑"（Claude 及其 harness）与"双手"（沙箱和工具）和"会话"（事件日志）解耦，将三者视为独立接口，任何一个的失败或替换都不会干扰其他部分。

此前的耦合设计意味着单个容器失败会导致所有状态丢失。新架构让每个组件可以独立失败：沙箱崩溃返回工具调用错误，harness 失败后新实例通过 `wake(sessionId)` 从会话日志恢复。这使中位首次 token 时间降低了 60%，P95 延迟降低超过 90%。

会话日志还解决了长任务的上下文窗口限制：大脑无需不可逆地压缩消息，而是通过从事件流中获取位置切片来查询上下文，可按需回溯或跳跃。"我们无法预测未来的模型将需要什么具体的上下文工程策略。"
