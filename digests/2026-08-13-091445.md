**Anthropic Engineering: An update on recent Claude Code quality reports**

Anthropic published a detailed postmortem on three separate issues that caused Claude Code quality degradation over recent months. First: on March 4, the default reasoning effort was quietly downgraded from `high` to `medium` to reduce long latency — the wrong tradeoff. It was reverted April 7; all users now default to `xhigh` effort for Opus 4.7 and `high` for other models. Second: a caching optimization shipped March 26 had a bug — instead of clearing old thinking once after a session went idle, it cleared thinking on *every subsequent turn*, causing Claude to appear forgetful and repetitive. Fixed April 10. Third: a system prompt addition on April 16 capping response length to ≤25 words between tool calls cut coding quality measurably. Reverted April 20. As of April 23, Anthropic is resetting usage limits for all subscribers.

🔗 https://www.anthropic.com/engineering/april-23-postmortem

Anthropic发布了详细的事后复盘，揭示了近几个月导致Claude Code质量下降的三个独立问题。其一：3月4日，默认推理努力级别从`high`悄然降至`medium`以减少长时延，这是一个错误的权衡取舍，已于4月7日回滚；所有用户现在默认使用Opus 4.7的`xhigh`努力或其他模型的`high`努力。其二：3月26日上线的缓存优化存在bug——原本应在会话空闲后一次性清除旧的思考内容，却变成了*每一轮*都清除，导致Claude表现得健忘且重复。4月10日已修复。其三：4月16日新增的系统提示，将工具调用间的回复限制在≤25个词，导致编程质量明显下降，已于4月20日回滚。截至4月23日，Anthropic正在为所有订阅用户重置使用限额。

**Anthropic Engineering: Scaling Managed Agents — Decoupling the brain from the hands**

A deep architectural post on how Anthropic built Managed Agents by separating three components that were previously coupled into one container: the **brain** (Claude + harness), the **hands** (sandboxes and tools), and the **session** (durable event log). Decoupling meant each component could fail and recover independently — no more "pet" containers that needed nursing. The payoff: p50 time-to-first-token dropped ~60% and p95 dropped over 90% since containers are only provisioned when needed. Security improved too — credentials never enter the sandbox where Claude's generated code runs. The post also covers how the session log serves as a recoverable context object that lives outside Claude's context window, addressing the irreversibility problem in long-horizon context management.

🔗 https://www.anthropic.com/engineering/managed-agents

这篇深度架构文章详细介绍了Anthropic如何通过拆分原本耦合在单一容器中的三个组件来构建Managed Agents：**大脑**（Claude + harness）、**双手**（沙箱和工具）以及**会话**（持久化事件日志）。解耦意味着每个组件可以独立失败和恢复，不再有需要"精心护理"的"宠物"容器。收益显著：p50首次响应时间降低约60%，p95降低超过90%，因为容器仅在需要时才被创建。安全性也得到提升——凭证永远不会进入运行Claude生成代码的沙箱。文章还介绍了会话日志如何作为存在于Claude上下文窗口之外的可恢复上下文对象，解决了长时任务上下文管理中的不可逆问题。

🔗 https://www.anthropic.com/engineering/managed-agents

**AI & I by Every: Microsoft's Vision for an Internet Made for Agents With CTO Kevin Scott (Best of the Pod)**

**The Takeaway:** The agentic web isn't a metaphor — it's the next phase of the internet, and the open protocols being built now (MCP as HTTP, NL web as HTML) will outlast any single AI company's choices.

Microsoft CTO Kevin Scott has been programming for 41 years — started at 12, still uses vi — and he frames the current AI moment not as a rupture but as another turn in a long cycle of tool-driven change in software development. His most important concept is the **capability overhang**: model reasoning has already outpaced what products are delivering to users. The industry's near-term job is to close that gap, not wait for the next model leap.

Scott's central thesis is that agents need an ecosystem the way the internet needed HTTP and HTML. MCP plays the role of HTTP: a simple, open protocol that lets agents talk to any system. NL web plays the role of HTML. Neither needs to be proprietary. "One of the things as CTO that I've been pushing for at Microsoft is I want all of our systems internally to speak a standard protocol to all of the agents we're writing inside of Microsoft" — not because it's idealistic, but because shipping your org chart through your agent stack is a real engineering horror.

On security, he's candid: "I don't know exactly what the right security model is." But he thinks MCP's simplicity makes it easier for the community to converge on one. His concrete ask: agent identities, entitlement systems, and explicit permission requests before touching sensitive resources.

On the craft debate — are you a real programmer if you use AI agents? — he reaches for woodworking. In his teens, the debate was whether using power tools made you a real woodworker. Now it's CNC. "If you value the process more than the outcome, you'll make different decisions than people who value the outcome more than the process." His own advice: "Be curious. Try. And if it works for you, use it. And if it doesn't, don't."

His prediction for next year: the shift from synchronous to asynchronous agent interaction. Instead of prompting and waiting, you'll say "go sort this out" — and the agent will take its time, make dozens of calls, iterate, and come back to you with results.

🔗 https://www.youtube.com/playlist?list=PLuMcoKK9mKgHtW_o9h5sGO2vXrffKHwJL

**核心观点：** Agent网络不只是一个比喻——它是互联网的下一个阶段，而当下正在构建的开放协议（MCP相当于HTTP，NL web相当于HTML）将超越任何单一AI公司的选择而长久存在。

微软CTO Kevin Scott编程41年——12岁开始，至今仍用vi——他将当前的AI时刻定性为软件开发中工具驱动变革的又一轮循环，而非一次断裂。他最重要的概念是**能力悬挂**：模型的推理能力已经超前于产品对用户的实际交付。行业近期的任务是弥合这一差距，而非等待下一个模型飞跃。

Scott的核心论点是：agent需要一个生态系统，就像互联网需要HTTP和HTML一样。MCP扮演HTTP的角色：一个简单、开放的协议，让agent能与任何系统对话。NL web扮演HTML的角色。两者都不需要是专有的。"作为CTO，我一直在推动微软所有内部系统都能与我们编写的所有agent使用标准协议通信"——不是因为这是理想主义，而是因为让你的组织结构图通过agent技术栈"泄漏"出来，是真实的工程噩梦。
